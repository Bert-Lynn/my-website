后两层什么时候开始？

作品能够稳定运行之后，再比较关键词/向量检索、重排与消融。后训练先补PyTorch与SFT，再学DPO；GRPO需另核对算力与费用。DPO不等于在线RL。后两层是计划，不新增完成勾选，也不新增论文承诺；原研究继续独立推进。

每周通常6小时、最多8小时；论文投稿/返修周最多3小时。视频时长不是软件完成工期，练习和调试也计入每周预算。

当前只做这4项

1. 读取反馈，生成问题表

用合成反馈验证读取、去重、统计和引用。每个问题能找到对应反馈编号；不确定分类单列复核。

2. 接入AI，按要求生成报告

模型选择允许的工具，读取返回结果继续执行。说“只看2.1版本”后，查询范围、统计与生成文件一起改变。

3. 补测试，处理错误

缺列、空表、无证据或工具失败时会明确停止或有限重试。资料里的恶意指令只能当数据，不能越权读写。

4. 评测并整理演示

整理代码、依赖、启动说明、演示与真实对照评测。别人照说明试一次，你能现场改条件并解释变化。

你将演示的一次操作

这些是建议作品产出，不是本站已经生成的下载。实际演示只用公开、合成或明确获准的非敏感资料；输入限CSV与TXT/Markdown，结果按运行编号保存，不覆盖旧成果。

计数是去重后的反馈条数，不是人数；最常出现不等于最高业务优先级。模型账号、费用与安全凭据配置先确认；固定回放不能冒充真实Agent表现。

01 / 这份计划最终要做成什么？

你要逐步做出一个叫DemandDecisionLab的“需求预测与容量配置实验台”：导入一份小时级数据，查看数据问题，比较未来需求预测，再调整模拟资源预算，得到一份可解释、可重跑的报告。可以在本机演示，默认不要求公网部署。

一个直观例子

输入公开的自行车租赁计数，比较未来1小时或24小时的预测；假设每个时段可用资源有限，观察不同分配方法在模拟短缺、闲置成本上的差异。后期可加一个只读Agent，让它调用现有工具并解释结果。

它能把你的研究积累转成面试时可展示的证据：你如何清洗数据、避免信息泄漏、验证约束、处理失败、交付可运行工具。岗位要求会映射到这些证据，400–600元/天只是筛选目标，作品和课程都不能保证录用或薪资。

计划共配置13项能力、30个练习单元，按两条路线筛选必需内容。保留的53节原课程是补强与学习档案，47项原博士任务继续独立推进。你不需要从头重刷全部课程，也不需要同时完成两条路线。

数据与结论的边界

主项目使用UCI Bike Sharing公开数据（2011–2012年的小时/日租赁计数），保留来源、作者、CC BY 4.0许可链接及修改说明。它没有真实车队容量、站点调度、成本或收益；租赁计数也不等于全部潜在需求。

资源预算、时段容量、短缺与闲置惩罚由你设定，必须标为合成的“如果这样会怎样”情景。可以比较模拟结果，不能据此声称真实企业节省成本、已有企业客户或生产部署。

预测cnt时，不把同期casual、registered或预测时尚不可得的真实未来天气当成输入。航空数据迁移只用明确授权的资料或标明合成的数据，不上传导师、合作方或OAG私有数据。

02 / 先选一条路线，时间怎么算？

智能决策 / 预测与运筹

适合优先发挥需求研究、数学和运筹积累。先验证预测，再做约束优化，最后补工程交付。

  • 主线：11项能力、26个单元、6个里程碑。
  • 顺序：M0 → M1 → M2 → M3 → M4 → M6。
  • 约124小时；约76小时到M3，形成最小可演示版本（MVP）。M4形成可复现产品；M5的Agent接口可后补。

AI Agent应用工程

适合优先做接口、测试、工具调用与评测。预测和优化先用注明范围的固定基线或规则模拟。

  • 主线：9项能力、23个单元、5个里程碑。
  • 顺序：M0 → M1 → M4 → M5 → M6。
  • 约100小时；约50小时到M4，形成输入→校验→工具→报告的MVP。M2/M3为选修，不用等预测与运筹专项学完才做Agent。

在“目标实习”选择“运筹优化 / 决策算法”或“预测 / 机器学习应用”，都进入智能决策路线；选择“AI 应用 / Agent 工程”进入另一条路线。搜索/推荐和基础模型研究目前只供了解，没有配置完整可选主线。

  • 常规周：计划6小时，再留2小时应对调试或返工，总额最多8小时。阅读、练习、实现、验收和面试准备共用这份预算。
  • 论文投稿或返修周：最多3小时，做维护、复现或一个小变式；不为追赶月份额外熬夜补课。
  • 完整组合路线估计150小时。两条路线共享基础，124与100不能直接相加；也不要把两条路线同时塞进每周8小时。
  • 时间是规划的专注工作量估计，不是官方课时或完成保证。以76小时MVP为例，按8小时/周约10周，按6小时/周约13周；已有证据可减少重复学习，论文忙周、环境配置和返工会延长用时。
  • 默认用免费开源依赖、本地运行，不要求GPU、付费API或新云数据库。Agent可先做离线mock（固定模拟响应）；真实模型表现必须另测。

03 / 每个阶段具体留下什么？

下面是未来要产出的文件与演示示例，文件名可调整。完成与否以真实结果和验收证据为准，不以到了某个月为准。

M0 · 两条路线共用 · 约8小时

先把最小骨架跑起来

建一个项目目录，能读数据、执行脚本，并记录运行方法。

要留下的东西

  • README、环境说明、数据读取或生成脚本、至少2个边界测试。
  • 一份诊断记录：已会什么、卡在哪里、只需回查哪些章节。

怎样算做到：换到干净目录，按README跑出结果；结果带时间与数据hash（用于确认输入版本）。

M1 · 两条路线共用 · 约18小时

能导入数据，并看见检查结果

形成最早的可点击预览，先把输入和数据质量做可靠。

要留下的东西

  • Data Card（数据说明卡）、字段schema、SQL查询与pandas核对结果。
  • 本地小界面：选样例或上传CSV，看到缺失值、统计和错误行。

怎样算做到：坏字段有明确提示；文件大小/格式受限、默认不外传。固定JSON或预计算结果要注明，不能冒充实时预测。

M2 · 智能决策必需 / Agent选修 · 约26小时

比较可信预测，而非只报一个高分

用一致的时间切分比较季节朴素、线性、树模型，并说明哪里预测得不好。

要留下的东西

  • 统一训练与滚动验证入口，1小时/24小时预测报告。
  • 例如results/backtest.csv、切分清单、泄漏测试、分时段误差与失败分析。

怎样算做到：最终测试集锁定；各模型同切分比较；不偷看未来信息。没有“必须击败基线”的硬指标。

M3 · 智能决策必需 / Agent选修 · 约24小时

把预测接入模拟分配，做出MVP

允许调整预算、时段容量和模拟惩罚，比较均匀、贪心和优化方案。

要留下的东西

  • 优化模型、独立约束检查器、小实例穷举测试、敏感性结果表。
  • 一次完整演示：输入 → 预测 → 配置模拟约束 → 方案 → 报告。

怎样算做到：正确区分可行、不可行、超时；未证明最优就不标最优。所有成本差都限定为合成情景。

M4 · 两条路线共用 · 约24小时

让别人也能运行和试用

把脚本连成可用产品，补接口、网页、自动测试和失败路径。Agent路线在这里形成最早MVP。

要留下的东西

  • FastAPI接口、本地网页、CSV校验、参数配置、结果对照和报告导出。
  • 本地安装或Docker启动方式、自动测试与CI配置、一名真实试用者的问题记录与修复证据。

怎样算做到：一条命令启动，默认只监听本机、无需付费服务或密钥。报告能追溯数据版本、配置、状态和局限。没有真实试用反馈就保留该项未通过。

M5 · Agent必需 / 智能决策选修 · 约26小时

增加只读Agent，并分清测试范围

Agent只调用forecast、optimize、explain三个受限工具。工具负责数值与状态，Agent负责组织调用和解释。

要留下的东西

  • 工具schema、Agent调用循环、调用轨迹、延迟与任务结果报告。
  • 20个开发用例＋30个留出用例，注入、越权、非法参数、超时等测试；3分钟录屏或本地演示包。

怎样算做到：离线mock只证明协议和工程路径，不能证明真实LLM成功率。真实模型结果单独列；关键安全失败为0后才自评通过。

M6 · 两条路线共用 · 约24小时，可在产品成形后穿插

整理成可投递、可答辩的证据包

选择具体JD，逐条连接岗位要求、能力证据和仍未覆盖的缺口。

要留下的东西

  • README、架构图、Data Card、可复现结果、3分钟演示、失败案例和AI贡献说明。
  • 一张JD→技能→证据→缺口清单，以及2次模拟技术答辩记录。

怎样算做到：简历只写能核查的成果。毕业年份、城市、每周出勤、连续实习期与导师安排另外确认；目标岗位有额外要求时，只选一个补缺分支。

不默认再开第二个大型项目。只有具体JD确实需要时，才用8–12小时做一个小扩展，并替换同周主线时间。原有AirDemandLab、EnterpriseAgentLab、VisionLab记录仍保留在博士计划中。

04 / 第一次打开，按这5步做

  1. 先选一个主方向

    打开“目标实习”，点击方向卡里的“设为当前目标”。能力地图、主线学习数和项目必需项会跟着变化。岗位列表的“方向筛选”只是筛选样本，不会改变你的目标。

  2. 决定是否需要跨设备保存

    只在当前浏览器试用可以暂不登录。需要同步时，点击页面上的保存状态入口，进入“进度与账号”；用本网站同步账号登录或自己注册，收到验证邮件则确认后回来登录。

  3. 首次登录后，检查旧记录是否需要导入

    登录不会自动上传访客进度。确认是自己的账号后，点击“合并本机已有进度”并确认；有可导入记录时才出现此按钮。等状态显示“云端已同步”，再去另一台设备检查。

  4. 从“今天”的一次诊断开始

    点击“开始能力诊断”。首次准备可在“验收队列”选“读懂、修改并验证AI生成代码”；下载题目数据，按下一节的90分钟步骤动手。

  5. 保存真实结果，再决定补哪一课

    只勾选已有证据的验收项，填写“结果与复盘”，点击“保存这次实操自评”。没做完也可以保存部分结果。再点“查看这个技能的对应课程与学习进度”，只补本次暴露的缺口。

05 / 第一个90分钟，具体做什么？

目标是定位Python与AI代码审查的缺口。结束时尽量留下一个小脚本、至少3个测试和一段解释；没有做完就记录卡点，不延长成全天任务，也不因计时结束自动认定掌握。

开始前只需要这些

可运行Python 3的电脑、文本编辑器和终端。先用python3 --version检查环境（有些电脑命令叫python）。不需要先学SQL、pandas、Git或买API。若环境还没跑通，就把本次时间用于定位环境问题并记下报错；不把环境障碍当成技能失败。

下载现有题目数据与说明查看Python诊断对应章节回到站内学习路径

下载包提供题面、小数据和已知核对结果，没有完成代码或“给定脚本”。你可以自己写，也可以让AI按规格起草。站内位置：“能力与学习” → “学习路径” → “读懂、修改并验证AI生成代码” → “Python按需诊断与函数修复”（u-python-diagnostic）。

  1. 0–10分钟：打开题目，写下小规格

    解压后查看data_valid.csv和data_invalid.csv。先限定为Python练习：读取timestamp、market、count；按market输出sum、mean、count；重复键或缺失计数要报CSV行号与原因，不能静默丢弃。题面中的SQL、LEFT JOIN与窗口计算留给后续数据能力。

  2. 10–25分钟：建立并运行最小脚本

    创建validate.py，约定从命令行接收CSV路径并输出JSON；允许AI用Python标准库起草。把输入、输出、零计数、空文件和错误处理写清。按约定运行python3 validate.py data_valid.csv，保留实际输出。

  3. 25–45分钟：核对结果，审查一次改动

    合法数据应有A：sum=22、mean=11、count=2；B：sum=8、mean=4、count=2。重点检查B的0是否被错当空值、重复记录是否被累计。保留修改前后文件或diff，并说明一个真实问题如何修复；若未发现问题，就如实记为尚未完成该验收项。

  4. 45–65分钟：至少补3个测试

    在test_data.py里用标准库unittest检查：正常输入得到上述结果；空数据按你写明的规则处理；非法字段/重复记录报错并给出行号。data_invalid.csv第6行是重复键，第7行count缺失（表头算第1行）。运行python3 -m unittest -v test_data.py，保存真实输出；再补负数或坏时间戳作为后续边界。

  5. 65–80分钟：自己解释并尝试变式

    不用AI直接给答案，解释字典如何累计、为什么0不能当缺失、异常怎样返回。再尝试按日期聚合并改成按周，自己补跨年输入，说明周编号应同时考虑周所属年份。没做出来就记录具体卡点，留到补课后复测。

  6. 80–90分钟：存一份证据和下一步

    保存validate.py、test_data.py、输出文件、修改差异和简短复盘。回到该技能验收页，只勾选确实完成且有证据的项；填写本地文件位置、运行命令、实际结果、AI帮助范围和未完成部分，再保存自评。可以先不填网页链接。

这次练习支持哪些验收？什么情况下还不能通过？
  • 规格＋AI改动审查，支持第1项；必须真实指出至少一个实质问题，不能只写“已检查”。
  • 脚本修复＋正常/空数据/非法字段测试，支持第2项。第一次跑通不代表所有边界都测过。
  • 本人独立解释＋分组口径变式，支持第3项；只复制AI答案不算完成。
  • diff、复现命令、真实输出与AI辅助说明，支持第4项；Git commit可在后续Git单元补齐，先保留修改前后文件。
  • 四项必须全部有证据才勾选全部。只有一个脚本、截图或一段视频不能替代可重跑代码和测试；公开样例与变式不是独立认证考试。

卡在条件判断、循环或函数时，只回查Python官方教程4.1–4.4和函数定义/参数；再按缺口补容器、文件、异常或模块。需要学习如何给AI写规格和审查改动时，打开同组“AI辅助开发：规格→差异审查→测试”，不要先重刷整套长课。

06 / 平时一周怎么用？

  1. 开始一周：选一个交付

    看“今天”的下一项能力和“下一次项目交付”，只挑一个能在本周推进的小结果，例如“非法CSV能报出错误行”。同时检查博士计划，投稿/返修优先。

  2. 先尝试，再有针对性地学

    先看该技能的验收标准。能做就直接留下证据；做不出才去“学习路径”展开对应单元的“练习与学习范围”，点击“打开资料”，读指定范围并完成练习。

  3. 把练习接回同一个项目

    尽量直接改DemandDecisionLab中的数据、测试或接口，避免每学一节另建一个孤立Demo。同一份代码和结果可支持相关验收，不重复计时。

  4. 周末收尾：保存并确定下一步

    复跑本周改动，记录真实输出，分别更新学完单元、技能自评、项目状态。没做完的保持未完成；写清下次从哪里继续，检查同步状态。

一个6小时示例

20分钟回顾岗位与本周目标；1小时按缺口读资料；3小时40分钟实现与测试；1小时整理证据与复盘。余下2小时只是缓冲，不必每周用满。忙于论文时把总量压到3小时。

“今天”按所选路线和已有自评记录推荐下一项，并不会自动判断代码质量。能力先后有依赖；有现成同等证据可以直接验收，没通过的先补缺口。

08 / 学完、技能通过、项目完成，有什么区别？

  • 学完单元：你按该单元范围完成了学习和练习。勾选只更新学习记录，不自动授予技能通过。
  • 技能通过：验收量表全部满足，并有证据。网站显示“实操通过 · 自评”，没有外部老师或雇主审核；分数是验收项覆盖率，不是能力排名或录用概率。
  • 项目完成：该里程碑交付物与标准逐项满足，提供有效HTTP(S)证据链接并勾选确认，再保存“已完成验收（自评）”。
  • 原博士任务：仍是另一组独立记录。新单元、旧课程、技能、作品和原任务不会互相自动勾选。
如何填写一份有用的证据？

技能自评可填仓库/报告/演示网址，也可先填写至少20字的结果说明；链接不是必填。说明应包含本地文件或仓库位置、commit（已有时）、环境、运行命令、输入、实际输出、AI辅助范围、本人修改和已知不足。20字只是表单最低要求，不是证据充分的标准。

文件/版本：[实际位置与版本]；运行：[实际命令]；输入：[数据文件与来源]；结果：[真实测试数、指标或报错]；我独立做了：[审查、修改、解释]；AI帮助了：[具体范围]；仍未完成：[对应量表项与下一步]。

网站只保存你填写的记录，不执行代码，不验证外部仓库是否真实，也不会自动上传本地文件。项目里程碑的“已完成验收”目前必须有证据链接；成果只有本地文件时，可先保持“进行中”，整理可访问的证据链接后再标完成。分享前自行检查数据、隐私与访问权限。

勾错了或发现原结果有问题，怎么撤回？
  • 学习单元或原课程：取消对应勾选即可；重做完成时会记录新的完成时间。
  • 技能自评：重新打开该技能，取消缺乏证据的验收项，补充原因并再次保存；它会回到“实操待达标”。不是点一个“撤销掌握”按钮。
  • 项目里程碑：把推进状态改回“进行中”或“待推进”，点击“保存里程碑状态”。
  • 旧验收尝试会保留有限的历史记录供复盘；页面历史摘要不是完整文件版本库，原始代码和证据仍要自己保留。
  • 不要用重置全部任务代替修正一条记录；三类进度本来就应分别维护。

09 / 记录保存在哪里？换电脑怎么办？

未登录时，记录保存在当前浏览器。换浏览器、换电脑或清除网站存储，不会自动带上这份访客记录。登录后使用个人账号同步，公开网站只发布路线与岗位资料。

  • 第一次登录：先确认账号身份，再按需点击“合并本机已有进度”。注册或登录本身不会自动导入。
  • 换设备：在另一台设备登录同一个网站同步账号，查看最新记录。确认原设备显示“云端已同步”，不要只看勾选还在。
  • 离线/待同步：修改会先留在设备，恢复后重试；可以用“立即同步”检查状态。错误或冲突没有解决前，不应声称同步完成。
  • 两台设备冲突：先核对哪些修改要保留，再选“采用云端版本”或“保留本机版本”；选择会替换相应版本，不能凭感觉连续点击。
  • 退出登录：恢复该浏览器的访客记录，账号记录不会自动混入另一个账号。证据里不要填密码、API密钥、访问令牌或私有研究数据。
